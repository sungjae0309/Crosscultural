# 실험 설계 초안 (2판)

상태: 초안 2판. 외부 검토(GPT) 1회를 반영했고 팀이 확인했다 (H3 추가, 15절 기준값). 외부 재검토 후 확정한다.
확정한 뒤에는 결과를 보고 바꾸지 않는다. 바꿔야 하면 바꾼 이유를 14절에 남긴다.
숫자 기준값은 모두 `src/config.py`에 있다. 이 문서의 숫자와 다르면 config가 맞다.

## 1. 질문

음악 서비스가 새 나라에 진출할 때, 추천 목록에서 "전체 인기 아티스트"와 "그 나라 인기 아티스트"를 어떤 비중으로 섞어야 하는가. 그리고 나라의 가치관(WVS)이 이 결정에 도움이 되는가.

- H1. 나라마다 최적 비중이 다르고, 나라별 비중이 모든 나라 공통 비중보다 추천이 잘 맞는다.
- H2. 초기 사용자가 적은 새 나라는, WVS 가치관이 비슷한 나라의 비중을 빌려 쓰면 공통 비중보다 추천이 잘 맞는다.
- H3. H2의 효과는 협업 필터링(CF) 위에서도 남는다. 즉 WVS로 빌린 비중이 CF만 쓰거나 CF에 공통 비중을 쓸 때보다 낫다.

H3을 넣은 이유: 과제 옵션 A가 "나라 가치관이 CF를 넘어 아티스트 순위를 개선하는가"를 묻는다 (`Midterm_CrossCulturalRecommendationSystems.pdf` 17쪽).

## 2. 데이터

| 항목 | 내용 |

| Last.fm 360K | 사용자별로 많이 들은 아티스트(사용자당 중앙값 49개)와 재생 수, 프로필 국가. 2008~2009년 한 시점 기록이라 시간 순서는 없다 |
| WVS Wave 5 | 2004~2009년 조사, 58개 나라, 83,975명 |

| 정리 후 | 사용자 358,630명, 235개 나라, 아티스트 268,775개 |

데이터 확인 결과는 `results/tables/data_check.md`.

## 3. 대상 나라

| 실험 | 조건 | 나라 수 |
|---|---|---|
| H1 | Last.fm 사용자 `MIN_USERS_PER_COUNTRY`(100)명 이상 | 75 |
| H2, H3 | 위 조건 + WVS에 있음 + 사용자 `MIN_USERS_H2`(200)명 이상 | 42 |

H2 기준을 더 높인 이유: 새 나라 역할을 할 때 초기 사용자 50명을 학습 사용자에서 뽑고, 시험 사용자도 30명 이상 남아야 결과가 덜 흔들린다.
최종 대상 나라별 학습·검증·시험 사용자 수와 평가에 쓰인 사용자 수는 표로 따로 낸다.

## 4. 사용자 나누기와 평가 방법

- 나라마다 사용자를 학습 70% / 검증 15% / 시험 15%로 무작위로 나눈다. 시드 고정. 모든 모델이 같은 시험 사용자를 쓴다.
- 학습 사용자: 인기 점수와 CF를 만드는 데만 쓴다.
- 검증 사용자: 비중과 CF 설정을 고르는 데만 쓴다.
- 시험 사용자: 마지막 비교에 한 번만 쓴다.
- 검증·시험 사용자는 아티스트 중 `N_SHOWN_ARTISTS`(5)개를 무작위로 골라 "이미 아는 것"으로 주고, 나머지를 정답으로 둔다.
  - 과제 자료의 "새 나라 사용자에게 정해진 만큼의 이전 기록을 준다"에 해당한다.
  - 인기 모델에서는 이 5개를 추천 목록에서 빼는 데만 쓴다. CF에서는 사용자 입력으로 쓴다.
  - 시간 정보가 없어서 "다음에 들을 것"을 맞히는 실험은 아니다. 숨긴 취향을 맞히는 실험이다.
- 아티스트가 `MIN_ARTISTS_EVAL_USER`(10)개보다 적은 사용자는 평가에서 뺀다. 학습에는 쓴다.

### 4.1 순위를 매기는 아티스트 집합

- 각 실험 조건에서 쓸 수 있는 학습 자료에 한 번이라도 나온 아티스트만 순위를 매긴다. 시험·검증 사용자의 기록으로 집합을 만들지 않는다.
- 이 집합에 없는 정답 아티스트도 정답 수(분모)에 그대로 남긴다. 그래서 학습 자료에 없는 아티스트는 맞힐 수 없고, 그만큼 점수가 낮게 나온다.
- 정답 중 이 집합에 들어 있는 비율(아이템 겹침)을 나라별로 보고한다.
- 점수가 같으면 전체 청취자 수가 많은 쪽, 그다음 artist_id 순으로 정한다.
- 음성 샘플링(일부 아티스트만 뽑아 순위 매기기)은 하지 않는다.

### 4.2 지표

- NDCG@10: 주 지표. 비중 고르기와 가설 판정에 쓴다.
- Recall@10: 맞힌 정답 수 / 전체 정답 수. 과제 자료의 정의를 따른다.
- 아이템 커버리지: 한 방법이 시험 사용자 전체에게 추천한 서로 다른 아티스트 수 / 순위를 매긴 아티스트 수.
- 정답은 들었는지 여부(0/1)만 본다.

## 5. 인기 점수와 섞기

- 인기 점수 = 그 아티스트를 들은 학습 사용자 비율 (0~1).
  - 전체 인기: 그 조건에서 쓸 수 있는 모든 나라 학습 사용자 기준.
  - 나라 인기: 그 나라 학습 사용자 기준.
- 재생 수 합 대신 청취자 비율을 쓰는 이유: 재생 수는 소수의 많이 듣는 사용자에게 크게 끌려간다. 재생 수 합은 보조 분석으로만 본다.
- 섞은 점수 = (1 - w) × 전체 인기 + w × 나라 인기
  - w = 0이면 전체 인기만, w = 1이면 나라 인기만 쓴다.
  - w 후보: 0, 0.1, ..., 1.0 (`WEIGHT_GRID`).

## 6. 모델

과제 자료의 비교 틀(target-only, pooled, transferred)에 맞춰 정리했다.

| 이름 | 내용 | 과제 자료의 역할 |
|---|---|---|
| P0 전체 인기 | w = 0 | pooled 기준선 |
| P1 나라 인기 | w = 1 | target-only |
| P2 공통 비중 | 모든 나라에 같은 w | pooled + 나라 정보 |
| P3 나라별 비중 | 나라마다 고른 w (H1). H2에서는 상한 참고값 | 나라 ID만 쓴 비교 |
| P4 WVS 유사국 비중 | WVS로 가까운 나라의 w를 빌림 | transferred + 문화 정보 |
| P5 무작위 나라 비중 | 무작위로 고른 나라의 w를 빌림 | 문화 정보 제거 실험 |
| C0 CF | ALS (`implicit` 패키지) | 개인화 기준선 |
| C1 CF + 공통 비중 | CF 점수와 나라 인기를 공통 w로 섞음 | CF + 나라 정보 |
| C2 CF + WVS 비중 | CF 점수와 나라 인기를 WVS로 빌린 w로 섞음 | CF + 문화 정보 |
| C3 CF + 무작위 비중 | CF 점수와 나라 인기를 무작위로 빌린 w로 섞음 | 문화 정보 제거 실험 |

- CF와 나라 인기를 섞을 때는 두 점수를 사용자마다 순위 대상 아티스트 안에서 0~1로 맞춘 뒤(최소-최대) 섞는다.
- CF 설정(잠재 요인 수, 정규화)은 검증 사용자로 고른다. 후보는 `CF_FACTORS_GRID`, `CF_REG_GRID`.
- 평가 사용자의 CF 벡터는 보여준 5개 아티스트만으로 계산한다 (학습을 다시 하지 않는 fold-in).
- 아티스트 속성(장르, 텍스트)을 쓰는 콘텐츠 모델은 넣지 않는다. Last.fm 360K에 아티스트 속성이 없기 때문이다.
- ALS를 고른 이유: `implicit` 패키지에서 fold-in을 바로 지원한다. 과제 자료가 예로 든 BPR은 보조 비교로 남긴다.

## 7. H1 실험

1. 나라 c마다 검증 사용자 NDCG@10이 가장 높은 w를 고른다. 이것이 나라별 비중 w_c.
2. 공통 비중: 하나의 w로 나라별 검증 NDCG@10의 평균(나라마다 같은 무게)이 가장 높은 값. 사용자 수로 가중하지 않는 이유는 미국 한 나라(6.7만 명)가 결과를 좌우하기 때문이다. 사용자 수 가중 결과는 보조로 낸다.
3. 시험 사용자로 나라마다 P0, P1, P2, P3의 NDCG@10을 계산한다.
4. 판정
   - "최적 비중이 다르다": w_c의 분포를 그림으로 보여준다.
   - "나라별이 공통보다 낫다": P3 - P2 차이로 판정한다 (11절의 통계 방법).
- 주의: 사용자가 적은 나라는 검증 사용자도 적어서 w_c가 우연히 정해질 수 있다. 그래서 검증에서 고르고 시험에서 비교한다. 결과는 나라 크기별로 나눠서도 본다.

## 8. H2 실험

새 나라 t 하나를 정하고 나머지 나라만 아는 상황을 만든다. H2 대상 42개 나라를 차례로 t로 둔다.
후보 나라 풀(빌려올 나라)은 t를 뺀 H2 대상 나라 41개다. 모든 방법이 같은 풀을 쓴다.

### 8.1 새 나라 t의 상황

- t의 나라 인기는 t의 학습 사용자 중 무작위로 뽑은 `N_EARLY_USERS`(50)명으로만 만든다.
- 전체 인기는 t를 뺀 나라들의 학습 사용자로 만든다.
- 순위 대상 아티스트는 t를 뺀 나라의 학습 사용자 + t의 초기 사용자 50명의 기록에 나온 아티스트다.
- t의 검증·시험 사용자, t의 나머지 학습 사용자, t에서 고른 w는 쓰지 않는다. (P3 상한값만 예외로 t의 검증 사용자를 쓰고, 이 값은 비교 판정에 쓰지 않는다.)
- 초기 사용자 뽑기를 `N_EARLY_REPEATS`(10)번 반복한다. 반복 결과는 나라마다 먼저 평균 내서, 나라 하나가 표본 하나가 되게 한다. 반복 간 흔들림도 함께 보고한다.

### 8.2 빌려올 나라 c의 비중 (t마다 다시 계산)

- c도 새 나라처럼 다룬다. c의 나라 인기는 c의 학습 사용자 50명으로만 만든다.
- 이때 전체 인기에서는 t와 c를 모두 뺀다.
- c의 검증 사용자로 w별 NDCG@10을 계산해 둔다.
- 이유: 나라 인기를 수천 명으로 만들 때와 50명으로 만들 때는 믿을 만한 정도가 달라서 최적 w도 다르다. 새 나라는 50명 조건이니 빌려오는 쪽도 같은 조건에서 구한다.

### 8.3 t에 쓸 비중 고르기

| 방법 | t에 쓰는 w |
|---|---|
| P0 전체 인기 | 0 |
| P1 나라 인기 | 1 (초기 사용자 50명으로 만든 나라 인기만) |
| P2 공통 비중 | 풀 41개 나라의 검증 NDCG@10 평균이 가장 높은 w |
| P4 WVS 유사국 | WVS 거리가 가장 가까운 `WVS_NEIGHBORS_K`(3)개 나라의 검증 NDCG@10 평균이 가장 높은 w |
| P5 무작위 나라 | 무작위로 고른 3개 나라의 검증 NDCG@10 평균이 가장 높은 w. `N_RANDOM_REPEATS`(100)번 반복해서 평균 |
| P3 상한 (참고) | t 자신의 검증 사용자로 고른 w |

- 세 나라의 최적 w를 평균 내지 않고 세 나라 검증 성능의 평균이 가장 높은 w를 고른다. 나라 하나의 최적 w가 우연히 튀는 영향을 줄이기 위해서다.

### 8.4 판정

- 주 비교: P4 - P2.
- 보조 비교: P4 - P5 (WVS가 우연보다 나은지), P4 - P1 (빌린 비중이 나라 인기만 쓰는 것보다 나은지).

## 9. H3 실험 (CF 위에서 같은 비교)

- t마다 t를 뺀 나라의 학습 사용자로 ALS를 학습한다. t의 초기 사용자는 CF 학습에 넣지 않고 나라 인기에만 쓴다.
- C1, C2, C3의 w는 8.2~8.3과 같은 방식으로 고르되, 섞는 대상이 "전체 인기" 대신 "CF 점수"다.
- 주 비교: C2 - C1. 보조 비교: C2 - C0, C2 - C3.

## 10. WVS 나라 거리

- 지표: 코드북에 있는 Welzel의 종합 지수 두 개.
  - `SACSECVAL`: 세속적 가치. 대체로 0~1 (실제 최댓값 1.0035)
  - `RESEMAVAL`: 해방적 가치 (0~1)
- 나라값: 응답자 가중치 `V259`를 쓴 나라별 평균. 결측(빈칸, 음수 코드)은 뺀다. V259는 질문지와 코드북에 가중치 변수로 정의되어 있다.
- 거리: 두 지표를 표준화한 뒤 유클리드 거리. 표준화의 평균과 표준편차는 t를 뺀 풀 41개 나라로 구하고 t에는 같은 변환만 적용한다.
- 이 지표를 고른 이유: 문항을 직접 고르면 결과를 보고 고쳐 고르고 싶은 유혹이 생긴다. 이미 만들어진 지수를 쓰면 그런 여지가 없다.
- 거리만 미리 확인한 결과 (추천 성능은 보지 않음)
  - 가까운 나라 3개 예시: 스웨덴 → 노르웨이, 독일, 슬로베니아. 브라질 → 칠레, 멕시코, 아르헨티나. 터키 → 조지아, 인도네시아, 인도.
  - 어색한 예: 한국 → 몰도바, 홍콩, 세르비아. 지표 두 개짜리 거친 대리값이다.
  - 두 지표의 상관계수 0.44.
- 보조 분석: k = 1, 5. 주 분석은 바꾸지 않는다.

## 11. 통계 방법

모든 비교는 나라 하나를 표본 하나로 둔다 (H1 75개, H2·H3 42개).

- 주 결과
  - 나라별 시험 NDCG@10 차이의 평균과 중앙값
  - 차이의 평균에 대한 95% 부트스트랩 신뢰구간 (나라를 다시 뽑기, `N_BOOTSTRAP`(10,000)번)
  - 좋아진 나라의 비율
- 보조 검정: Wilcoxon 부호순위 검정, 양측, 유의수준 0.05, 차이가 0인 나라는 Pratt 방식으로 처리.
- 나라끼리 완전히 독립은 아니다 (전체 인기와 CF를 같이 쓴다). 그래서 검정의 p값보다 신뢰구간과 효과 크기를 먼저 해석한다.
- 가설마다 주 비교를 하나씩 미리 정했다 (H1: P3 - P2, H2: P4 - P2, H3: C2 - C1). 나머지는 보조로만 해석한다.

## 12. 실패 분석

WVS 비중이 공통 비중보다 나빴던 나라를 따로 본다.
- 나라 크기, 아이템 겹침, 가장 가까운 나라와의 WVS 거리, t의 최적 w와 빌린 w의 차이
- 자기 나라 아티스트 비중이 큰 나라(예: 언어권이 독립된 나라)에서 실패가 몰리는지

## 13. 정보가 새는 경로 점검

| 경로 | 막는 방법 |
|---|---|
| 시험 사용자를 보고 w나 CF 설정을 고름 | 검증 사용자로만 고른다 |
| 평가 사용자의 정답이 인기 점수나 CF에 들어감 | 학습 사용자로만 만든다 |
| 순위 대상 아티스트를 시험 기록으로 만듦 | 그 조건의 학습 자료로만 만든다 |
| H2에서 t의 데이터가 전체 인기, CF, 순위 대상에 들어감 | t를 빼고 다시 만든다. 초기 사용자 50명만 예외 |
| H2에서 빌려올 나라 c의 비중을 고를 때 t나 c의 나머지 사용자가 들어감 | 전체 인기에서 t와 c를 빼고, c는 50명만 쓴다 |
| H2에서 공통 비중에 t가 들어감 | 공통 비중도 t를 뺀 풀로 다시 고른다 |
| WVS 표준화에 t가 들어감 | 표준화도 t를 뺀 풀로 한다 |
| 결과를 보고 WVS 지표나 k를 바꿈 | 이 문서를 확정한 뒤 바꾸지 않는다 |

## 14. 보고서에 적을 한계

- Last.fm 국가는 사용자가 고른 값이라 거주지, 국적, 문화를 구분하지 못한다.
- Last.fm 이용자와 WVS 국민 표본은 대표하는 집단이 다르다.
- 나라 평균 가치관을 개인 취향에 적용하는 생태학적 오류와 고정관념 위험이 있다.
- WVS 조사 시점이 나라마다 2004~2009년으로 다르다. Last.fm은 2008~2009년이다.
- Last.fm 360K는 전체 청취 이력이 아니라 사용자별 상위 아티스트의 한 시점 기록이다.
- 나라별 음원 카탈로그, 언어, 라이선스 차이를 관찰하지 못한다.
- 같은 아티스트가 MusicBrainz ID 있는 기록과 없는 기록으로 나뉜 경우가 있다. 이름이 ID 하나와 정확히 맞는 경우가 전체 기록의 0.1%(아티스트 1,711개)라 합치지 않았다.
- 오프라인 실험이라 실제 진출 성과나 인과 효과를 증명하지 못한다.
