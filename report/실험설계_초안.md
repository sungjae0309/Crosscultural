# 실험 설계 초안

상태: 초안. 팀 검토와 외부 검토(GPT)를 거쳐 확정한다.
확정한 뒤에는 결과를 보고 바꾸지 않는다. 바꿔야 하면 바꾼 이유를 이 문서에 남긴다.
숫자 기준값은 모두 `src/config.py`에 있다. 이 문서의 숫자와 다르면 config가 맞다.

## 1. 질문

음악 서비스가 새 나라에 진출할 때, 추천 목록에서 "전체 인기 아티스트"와 "그 나라 인기 아티스트"를 어떤 비중으로 섞어야 하는가.

- H1. 나라마다 최적 비중이 다르고, 나라별 비중이 모든 나라 공통 비중보다 추천이 잘 맞는다.
- H2. 초기 사용자가 적은 새 나라는, WVS 가치관이 비슷한 나라의 비중을 빌려 쓰면 공통 비중보다 추천이 잘 맞는다.

## 2. 데이터

| 항목 | 내용 |
|---|---|
| Last.fm 360K | 사용자별로 많이 들은 아티스트(사용자당 중앙값 49개)와 재생 수, 프로필 국가. 2008~2009년 한 시점 기록이라 시간 순서는 없다 |
| WVS Wave 5 | 2005~2009년, 58개 나라, 83,975명 |
| 제외 | 실제 거주지로 보기 어려운 국가값 4개(사용자 717명). `config.EXCLUDED_ISO3` |
| 정리 후 | 사용자 358,630명, 235개 나라, 아티스트 268,775개 |

데이터 확인 결과는 `results/tables/data_check.md`.

## 3. 대상 나라

| 실험 | 조건 | 나라 수 |
|---|---|---|
| H1 | Last.fm 사용자 `MIN_USERS_PER_COUNTRY`(100)명 이상 | 75 |
| H2 | 위 조건 + WVS에 있음 + 사용자 `MIN_USERS_H2`(200)명 이상 | 42 |

H2 기준을 더 높인 이유: 새 나라 역할을 할 때 초기 사용자 50명을 학습 사용자에서 뽑고, 시험 사용자도 30명 이상 남아야 결과가 덜 흔들린다.

## 4. 사용자 나누기와 평가 방법

- 나라마다 사용자를 학습 70% / 검증 15% / 시험 15%로 무작위로 나눈다. 시드 고정.
- 학습 사용자: 인기 점수를 만드는 데만 쓴다.
- 검증 사용자: 비중을 고르는 데만 쓴다.
- 시험 사용자: 마지막 비교에 한 번만 쓴다.
- 검증·시험 사용자는 아티스트 중 `N_SHOWN_ARTISTS`(5)개를 무작위로 골라 "이미 아는 것"으로 보여주고, 나머지를 정답으로 둔다. 추천 목록에서 보여준 5개는 뺀다.
- 아티스트가 `MIN_ARTISTS_EVAL_USER`(10)개보다 적은 사용자는 평가에서 뺀다. 학습에는 쓴다.
- 지표: NDCG@10 (주 지표), Recall@10 (보조 지표). 정답은 들었는지 여부(0/1)만 본다.
- Recall@10은 맞힌 개수를 min(10, 정답 수)로 나눈다. 정답이 40개 넘는 사용자가 많아서 그냥 나누면 최댓값이 0.25 정도로 묶이기 때문이다.

## 5. 인기 점수와 섞기

- 인기 점수 = 그 아티스트를 들은 학습 사용자 비율 (0~1).
  - 전체 인기: 모든 나라 학습 사용자 기준.
  - 나라 인기: 그 나라 학습 사용자 기준.
- 재생 수 합 대신 청취자 비율을 쓰는 이유: 재생 수는 소수의 많이 듣는 사용자에게 크게 끌려간다. 재생 수 합은 보조 분석으로만 본다.
- 섞은 점수 = (1 - w) × 전체 인기 + w × 나라 인기
  - w = 0이면 전체 인기만, w = 1이면 나라 인기만 쓴다.
  - w 후보: 0, 0.1, ..., 1.0 (`WEIGHT_GRID`).

## 6. H1 실험

1. 나라 c마다 검증 사용자 NDCG@10이 가장 높은 w를 고른다. 이것이 나라별 비중 w_c.
2. 공통 비중: 하나의 w로 나라별 검증 NDCG@10의 평균(나라마다 같은 무게)이 가장 높은 값. 사용자 수로 가중하지 않는 이유는 미국 한 나라(6.7만 명)가 결과를 좌우하기 때문이다.
3. 시험 사용자로 나라마다 NDCG@10을 계산한다: 전체 인기(w=0), 나라 인기(w=1), 공통 비중, 나라별 비중.
4. 판정
   - "최적 비중이 다르다": w_c의 분포를 그림으로 보여준다.
   - "나라별이 공통보다 낫다": 나라별 시험 NDCG 차이(나라별 - 공통)에 대해 Wilcoxon 부호순위 검정 (나라 75개가 표본).
- 주의: 사용자가 적은 나라는 검증 사용자도 적어서 w_c가 우연히 정해질 수 있다. 그래서 검증에서 고르고 시험에서 비교한다. 결과는 나라 크기별로 나눠서도 본다.

## 7. H2 실험

새 나라 t 하나를 정하고 나머지 나라만 아는 상황을 만든다. H2 대상 42개 나라를 차례로 t로 둔다.

### 7.1 새 나라 상황 만들기

- t의 나라 인기는 t의 학습 사용자 중 무작위로 뽑은 `N_EARLY_USERS`(50)명으로만 만든다.
- 전체 인기는 t를 뺀 나라들의 학습 사용자로 만든다.
- t의 검증·시험 사용자, t의 전체 학습 사용자로 만든 인기 점수, t에서 고른 w는 쓰지 않는다.
- 초기 사용자 뽑기를 `N_EARLY_REPEATS`(5)번 반복해서 평균을 낸다.

### 7.2 빌려올 비중 만들기

다른 나라 c의 비중도 "초기 사용자 50명" 조건에서 다시 고른다. 즉 c의 나라 인기를 c의 학습 사용자 50명으로 만들고, c의 검증 사용자로 w를 고른다. 이 값을 w_c^early라고 한다.

이렇게 하는 이유: 나라 인기를 수천 명으로 만들 때와 50명으로 만들 때는 믿을 만한 정도가 달라서, 최적 w도 다르다. 새 나라는 50명 조건이니 빌려오는 비중도 같은 조건에서 구해야 맞다.

### 7.3 비교하는 방법

후보 나라 풀은 t를 뺀 H2 대상 나라(41개)로 모두 같게 둔다.

| 방법 | t에 쓰는 비중 |
|---|---|
| 전체 인기 | w = 0 |
| 공통 비중 | 풀 전체에서 나라별 검증 NDCG 평균이 가장 높은 하나의 w (50명 조건) |
| WVS 유사국 | WVS 거리가 가장 가까운 `WVS_NEIGHBORS_K`(3)개 나라의 w_c^early 평균 |
| 무작위 나라 | 풀에서 무작위로 고른 3개 나라의 w_c^early 평균. `N_RANDOM_REPEATS`(100)번 반복해서 평균 |
| 상한(참고용) | t 자신의 검증 사용자로 고른 w. 실제로는 알 수 없는 값 |

### 7.4 판정

- 주 비교: WVS 유사국과 공통 비중의 나라별 시험 NDCG@10 차이. Wilcoxon 부호순위 검정 (나라 42개가 표본).
- 보조 비교: WVS 유사국과 무작위 나라. WVS가 우연보다 나은지 본다.

## 8. WVS 나라 거리

- 지표: 코드북에 있는 Welzel의 종합 지수 두 개.
  - `SACSECVAL`: 세속적 가치 (0~1)
  - `RESEMAVAL`: 해방적 가치 (0~1)
- 나라값: 응답자 가중치 `V259`를 쓴 나라별 평균. 결측(빈칸, 음수 코드)은 뺀다.
- 거리: 두 지표를 H2 대상 나라 기준으로 표준화한 뒤 유클리드 거리.
- 이 지표를 고른 이유: 문항을 직접 고르면 결과를 보고 고쳐 고르고 싶은 유혹이 생긴다. 이미 만들어진 지수를 쓰면 그런 여지가 없다.
- 확인 결과 (추천 성능은 보지 않고 거리만 봄)
  - 가까운 나라 3개 예시: 스웨덴 → 노르웨이, 독일, 슬로베니아. 브라질 → 칠레, 멕시코, 아르헨티나. 터키 → 조지아, 인도네시아, 인도.
  - 어색한 예: 한국 → 몰도바, 홍콩, 세르비아. 지표 두 개라 거칠다.
  - 두 지표의 상관계수 0.44. 겹치는 정보가 있지만 같은 지표는 아니다.

## 9. 2단계 (인기 섞기 실험 뒤)

협업 필터링(ALS, `implicit` 패키지)을 비교 기준으로 넣고, 협업 필터링 점수에 나라 인기를 섞는 실험을 한다. 세부 설계는 1단계 결과를 보기 전에 따로 정한다.

## 10. 정보가 새는 경로 점검

| 경로 | 막는 방법 |
|---|---|
| 시험 사용자를 보고 w를 고름 | w는 검증 사용자로만 고른다 |
| 평가 사용자의 정답이 인기 점수에 들어감 | 인기 점수는 학습 사용자로만 만든다 |
| H2에서 t의 데이터가 전체 인기에 들어감 | t를 뺀 나라로 전체 인기를 다시 만든다 |
| H2에서 t의 정보로 비중을 고름 | 빌려오는 비중은 t를 뺀 풀에서만 만든다 |
| 결과를 보고 WVS 지표나 k를 바꿈 | 이 문서를 확정한 뒤 바꾸지 않는다 |

| 공통 비중 평균 방식 | 나라마다 같은 무게 | 사용자 수 가중 |

## 12. 외부 검토 요청 질문

1. 7.1에서 새 나라 t의 정보가 새어 들어가는 경로가 더 있는가.
2. 7.2처럼 빌려오는 비중도 "초기 사용자 50명" 조건에서 고르는 것이 맞는가. 아니면 전체 학습 사용자로 고른 w_c를 빌려야 하는가.
3. 공통 비중을 나라마다 같은 무게로 평균 내서 고르는 것이 H1, H2의 비교에 공정한가.
4. 나라 75개, 42개를 표본으로 한 Wilcoxon 부호순위 검정이 적절한가. 나라끼리 독립이 아니라는 점(전체 인기를 같이 씀)이 문제가 되는가.
5. 보여줄 아티스트 5개를 무작위로 고르는 방식이 맞는가. 재생 수 상위 5개로 고르는 것과 비교해 어느 쪽이 "새 사용자" 상황에 가까운가.
6. WVS 거리에 Welzel 지수 2개만 쓰는 것이 충분한가. 표준화를 H2 대상 나라 기준으로 하는 것이 맞는가.
7. Last.fm 국가 정보는 사용자가 고른 값이고, WVS는 2005~2009년 조사다. 이 둘을 연결하는 데 생기는 한계 중 보고서에 꼭 적어야 할 것이 있는가.
